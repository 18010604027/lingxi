# 灵犀（lingxi-pet）

一个独立运行的桌面陪伴助手。她通过桌面上的身体与你聊天、做动作、回应点击和拖动，也会记录互动、形成记忆，把需要较长时间处理的事情交给后台。

身体是主要交互入口。工作台用于查看完整对话、详细过程、后台任务、记忆和设置；日常使用不需要 DSH 桌面版。

## 交互与能力

- **身体聊天**：浮动输入、独立气泡、多段回复和思考提示；回复可以配合动作表达。
- **身体互动**：点击、拖动和放下会进入互动记录；动作记录开始与结束，供后续对话理解。
- **日常行为**：根据状态和环境选择活动，识别工作区域，按形象配置移动与避让。
- **记忆**：保留对话与事件，结合话题卡、关系图和检索提供后续上下文。
- **后台任务**：前台可以交办任务，执行期间继续聊天，再接收结果；需要用户判断时由前台提出问题。
- **独立工作台**：「此刻、后台、记忆、设置」共用同一 Core 状态。详细过程显示已有的前台事件、工具和后台记录；模型未提供的私有思维不生成展示内容。

## 三层分工

| 层 | 职责 |
|---|---|
| 前台 | 理解当前对话、组织回复、表达动作、转达需要用户判断的问题 |
| 行为系统 | 执行动作、安排移动、管理活动区域和日常行为 |
| 后台 | 处理较长任务，通过适配接口调用现成代码执行器 |

前台模型连接与代码执行器是两套配置。聊天通过配置的模型 API；代码任务通过通用任务接口接入现成 harness，当前已接通 Codex CLI。DSH 等接入保留在适配层，不是身体、工作台和普通聊天的运行前提。

## 从源码运行

需要 Node.js 22+ 和 pnpm 11。代码执行功能另需安装、配置并登录对应的外部执行器。

```sh
pnpm install
```

准备自己的形象包和动作素材后启动。形象包可以直接放在项目的 `packs/local/`：这个目录被 `.gitignore` 整个忽略，只在本地，不会提交也不会发布。没有形象包时，先按 [形象包格式](packs/README.md) 的最小示例创建配置，再把片段放入 `clips/`：

```powershell
$env:LINGXI_PACK = 'packs/local'
pnpm check:pack packs/local
pnpm start
```

如果你已经有形象包，也可以先让程序检查并记住它的路径：

```powershell
pnpm run setup:app -- --pack 'D:\MyFigure'
pnpm start
```

`setup:app` 不下载素材、不生成运动算法；会加载你选择的 `motion.cjs` 检查接口，确认后只保存包路径。`--check` 只检查不保存。检查失败时保留原来的选择。

放在别处也行，用 `LINGXI_PACK` 指给程序（见下文）。包里必须有 `figure.json`、`motion.cjs` 和 `clips/`，格式在 [packs/README.md](packs/README.md)。`motion.cjs` 是形象包自己的运动算法，灵犀不会替你提供默认实现。

启动入口会装配 Core、身体、工作台和托盘。工作台关闭后收回托盘；单击或双击托盘显示工作台，从托盘菜单退出应用。工作台也提供单独的开发入口 `pnpm workbench`，用于连接已启动的 Core。

在工作台「设置」中配置前台模型的 API 地址、模型名和 API Key。已存密钥不回显；留空保存会保留原密钥。名字、称呼、角色设定和对话选项也在设置页管理，具体生效时间以保存提示为准。首次启动按「模型连接 → 形象与人设确认 → 试聊」完成最小配置；以后可在设置页修改。

首次配置可跟随「模型连接 → 形象与人设确认 → 试聊」引导；以后可在设置页重新打开。形象沿用启动时选择的本地形象包。人设修改保存后用于后续模型请求，当前会话也会收到一条设定已变更的上下文提示。

后台执行设置只展示当前 adapter 实际支持的选项。Codex 可配置只读或任务目录可写、联网允许或禁止；这些选项沿用 Codex CLI 的沙箱能力，不另造一套沙箱。

开发检查使用 `pnpm typecheck`、`pnpm test` 和 `pnpm test:body`。`pnpm test:release` 需要一份完整的形象包（`figure.json`、`motion.cjs` 和片段，用 `LINGXI_PACK` 指定），它会以临时数据、本地模型替身和真实 Electron 窗口检查身体输入、可见回复、正常退出及同根重开，不读取个人配置或调用付费模型。

## 形象与动作配置

仓库不自带形象包，也没有任何动作素材。她长什么样、有哪些动作，由使用者自己提供一个形象包目录：

```text
<形象包目录>/
  figure.json       # 尺寸、点击区域、动作词、移动方式与片段映射
  clips/*.webm      # figure.json 引用的动画片段
  motion.cjs        # 运动算法（必需，见 packs/README.md）
```

`figure.json` 的字段和含义见 [packs/README.md](packs/README.md)，机器可读的版本是 [packs/figure.schema.json](packs/figure.schema.json)。包写错或缺少字段时，启动会直接报出是哪个字段。形象包里必须有 `motion.cjs`，提供走路、弹簧、抛掷速度和下落反弹这些运动算法；仓库不自带实现，格式在 [packs/README.md](packs/README.md)。

工作台「设置」里有两项跟行为有关：

- **避障**：开着时她绕开屏幕上的窗口和禁区；关掉后直接从上面走过，不再绕路。保存后立即生效。
- **动作**：每个动作播哪些片段、中文名、说明和什么时候用，可以在这里改。改动存在部署配置里，形象包文件不会被改写；换回形象包里的值，把这一项改回原样即可。

指定形象包：

```powershell
$env:LINGXI_PACK = 'packs/local'              # 形象包目录，也可以直接放在项目的 packs/<名字>/ 下
$env:LINGXI_CLIPS = 'D:\MyClips'              # 可选；默认用形象包里的 clips/ 目录
pnpm start
```

没有指定时读取 `~/.lingxi/pack` 里记录的路径；两处都没有，启动会停下来说明怎么指定。写完包可以先跑 `pnpm check:pack <形象包目录>` 单独检查，不用启动整个程序。行为怎么执行、走到哪里、怎么绕开窗口，属于本项目的动作系统和避障；某个动作具体是什么样，属于形象包。

## 数据与配置

源码默认部署的数据存放在 `build/` 下，不进入 Git。指定部署使用自己的数据目录；记忆、对话、角色设定、任务和凭据属于运行数据。

她自己的日常节奏（两次自主动作之间隔多久，`gap` 秒数区间）写在数据目录的 `daily/routine.json`；某个动作叫什么、长什么样、什么时候用，写在形象包的 `words` 和 `vocab` 里。

工作台通过本机 API 读取与操作 Core，连接凭据留在主进程。旧版数据迁移工具为 `pnpm move-data`，仅在确实需要迁移旧部署时使用，不是普通启动步骤。

## 项目结构

| 模块 | 目录 |
|---|---|
| 启动与装配 | `core/start.ts`、`core/application.ts` |
| 身体窗口、气泡、动画与互动 | `body/` |
| 形象包格式（仓库不含素材） | `packs/` |
| 行为执行与日常活动 | `core/behavior/`、`core/daily/` |
| 前台工具与共享输出 | `core/pet/` |
| 记忆 | `core/memory/` |
| 后台与执行器适配 | `core/agents/` |
| 运行时与框架接线 | `core/runtime/` |
| 独立工作台 | `workbench/` |
| 托盘与应用图标 | `tray/` |

## 扩展与开发

新增模型、工具、记忆、行为或执行器时，先看 [扩展指南](EXTENDING.md)，按所属模块接入，避免修改总装配和复制状态。形象包和代码执行器都是外部扩展，普通聊天不依赖代码执行器。

准备发布源码时运行 `pnpm prepare:release`。它核对相对导入、按白名单复制产品文件到新的临时目录，并在目录外生成清单与 SHA256；不会提交、推送或修改已有发布分支。候选不包含个人数据、素材包、内部设计与任务记录、旧宿主插件。候选使用当前跟踪文件及脚本明确准许的新文件，未提交改动也可能进入，发布前需核对清单和差异。
